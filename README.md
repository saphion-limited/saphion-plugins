# Saphion plugins

Saphion's own plugins for Beacon, in the Claude Code marketplace layout: `.claude-plugin/marketplace.json` lists them and each
folder is one plugin (`.claude-plugin/plugin.json`, `skills/<name>/SKILL.md`, scripts and references).

| Plugin | What it does |
| --- | --- |
| `saphion-documents` | Word and PDF files, spreadsheets and presentations, and documents inside Saphion |
| `design` | Palette, type and layout for pages, dashboards and single-file apps |
| `rams` | Risk assessments and method statements from an Organisation's own template |
| `tenders` | A source-grounded tender response prepared from a tender pack |
| `skill-creator` | Make or change your own skills by talking the job through with Beacon |

## Checks

Every pull request and push runs the `check` job: `scripts/check_repo.py` (layout, frontmatter) and the Beacon contract
(`python .saphion/plugin_contract.py .saphion/beacon-plugin-contract.json <plugin folder>...`), which refuses a skill that
names a tool Beacon does not have, a wrong choice for a tool, or an over-size skill. `main` requires the check.

## `.saphion/`

`.saphion/beacon-plugin-contract.json` and `.saphion/plugin_contract.py` are generated by the Saphion platform repository from the real
tools Beacon is offered. Never edit them here: the main repository's workflow keeps them current by pull request, so a tool removed
there turns this repository's check red at once.

## Releases

Saphion follows a tag, never the head of `main`. The **Promote** workflow (manual, behind the `production` environment's required
approval) cuts an immutable `release-<date>-<sha>` tag from a green commit on `main`.
